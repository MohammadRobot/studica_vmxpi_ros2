## Validation scope

Evidence is local software evidence, not physical acceptance:

- Humble scoped PC build: all three packages build; VMX hardware linking is
  intentionally skipped on PC. C++ and Python example executables are installed.
- `g++ -std=c++17 -fsyntax-only` against local Humble and cached vendor headers:
  `vmx_control_node.cpp`, `hardware/vmx_system.cpp`, driver `titan.cpp` pass.
- Native/container bundle fixtures: 8 verifier tests and 12 builder tests pass,
  including native provenance round-trip and rejection of PC native packaging.
- Driver velocity encoding tests cover signed rounding, NaN/infinity and the
  float scaling boundary near INT32_MAX. Conversion now uses double precision
  and validates the rounded value before casting. Both developer examples pass
  read-only defaults and bounded opt-in pulse/zero-output tests.
- RoboHiTec `make test`: contract validation, Go race tests/vet, frontend tests
  and Python tests pass using `tools/requirements.txt` in a temporary environment.
- RoboHiTec `make integration`: native worker/agent, graph/QoS/TF/diagnostics,
  authentication and mutation-denial tests pass in an isolated network namespace.
- ROS scoped suite passes across platform, monitor and drivers (excluding
  cppcheck and headless tests in that invocation). Headless Gazebo, mapping and
  navigation subsequently pass without skips: 51.53 s, 19.68 s and 24.28 s.
  The Studica native ROS observation fixture passes fresh/stale/duplicate/missing
  checks and clean shutdown with no command publisher. Earlier failures (XML download, native-profile static matcher,
  Python indentation and shellcheck source hints) were fixed rather than waived.

Final collected `colcon test-result --test-result-base build --verbose`:
**329 tests, 0 errors, 0 failures, 85 skipped**. The skipped cases are the
existing cppcheck result entries (19 platform, 66 driver); cppcheck was excluded
from this run. This is an aggregate of scoped invocations, not a new full lint
run. Logs are retained locally under `~/studica_ws/log/`: complete scoped run
`test_2026-11-10_20-43-44`, headless/additional checks
`test_2026-11-10_20-45-27`, and final driver/example/lint rerun
`test_2026-11-10_20-47-45`. The headless invocation initially failed only the
new Python example's executable permission; the final rerun passed after fixing
source permissions and making the fixture's log capture non-blocking.

`systemd-analyze verify` cannot fully validate the candidate installation on this

emit unrelated warnings. No unit was installed to satisfy that check. Native
builder invocation on x86 correctly refuses before compilation or hardware work.

Tests use synthetic messages/mock runtime, separate domains and network namespaces
with loopback only. No physical devices are passed through. No test here verifies
actual CAN delivery, motor stopping, the 80 ms end-to-end provenance limit, cold
boot or resource headroom. Full native ARM64 build, extended simulation acceptance and physical tests
remain separate gates. Headless SLAM/Nav2 smoke checks are not a classroom
multi-robot endurance campaign.
