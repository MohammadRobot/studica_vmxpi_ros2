# Lab 1 — Terminal, Workspace, Safety, and ROS Vocabulary

## Learning goals

- Source ROS 2 and the classroom workspace in every terminal.
- Distinguish a package, node, topic, message, service, parameter, and launch file.
- Apply the simulation and hardware safety boundaries.

## Prerequisites

- Ubuntu 22.04 and the simulation setup from [Installation](../INSTALL.md).
- No ROS or Gazebo process left running from another exercise.
- A notebook or text file for checkpoint answers.

## Terminals

### Terminal 1 — verify the environment

```bash
export STUDICA_WS="$HOME/studica_ws"
source "$HOME/.ros/studica_sim.env"
source /opt/ros/humble/setup.bash
source "$STUDICA_WS/install/setup.bash"
printenv ROS_DISTRO
ros2 pkg prefix studica_vmxpi_ros2
```

### Terminal 2 — practice workspace navigation

```bash
export STUDICA_WS="$HOME/studica_ws"
source "$HOME/.ros/studica_sim.env"
source /opt/ros/humble/setup.bash
source "$STUDICA_WS/install/setup.bash"
cd "$STUDICA_WS"
pwd
ls src
ros2 pkg list | grep -E '^(studica_vmxpi_ros2|studica_robot_monitor)$'
```

Do not work in `build`, `install`, or `log`; those are generated by `colcon`.

### Terminal 3 — inspect commands without starting anything

```bash
export STUDICA_WS="$HOME/studica_ws"
source "$HOME/.ros/studica_sim.env"
source /opt/ros/humble/setup.bash
source "$STUDICA_WS/install/setup.bash"
ros2 --help
ros2 topic --help
ros2 launch studica_vmxpi_ros2 sim.launch.py --show-args
```

`--show-args` describes a launch file but does not start the simulator.

## Expected output

- `ROS_DISTRO` is `humble`.
- The package prefix is below `$STUDICA_WS/install`.
- Both first-party packages appear in the package list.
- The simulation launch reports arguments such as `gui`, `gz_headless`,
  `use_camera`, `use_joystick`, and `world` without opening Gazebo.

## Checkpoint

Show the instructor the environment output and explain, in one sentence each:

- package: an installable unit of ROS code and resources;
- node: one running ROS participant;
- topic/message: a named stream and its typed data;
- service: a request followed by a response;
- parameter: named configuration owned by a node;
- launch file: a repeatable description of processes and configuration.

Also state the rule: simulation is independent work; real motors require an
instructor and a safety operator beside the emergency stop.
